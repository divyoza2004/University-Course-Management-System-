# University Course Management System

## 📌 Project Objective

This project implements a **Course Management System** database for a university, covering four core entities — **Departments, Instructors, Students, Courses**, and their relationships through an **Enrollments** table. The goal of the SQL script is to:

- Design a normalized relational schema with proper primary/foreign key constraints.
- Populate the schema with sample data.
- Demonstrate core **DML operations** (`INSERT`, `UPDATE`, `DELETE`, `SELECT`).
- Demonstrate **data analysis queries** using `JOIN`, `GROUP BY`, `HAVING`, aggregate functions (`AVG`, `MAX`, `COUNT`), and **subqueries**.

All query outputs below were generated by actually **executing the script in Python (`sqlite3`)** against the same data, in the same order as the original `.sql` file, so the tables shown are real, verified results — not guesses.

## 🗄️ Database Schema Overview

| Table | Purpose | Key Columns |
|---|---|---|
| `Departments` | Stores academic departments | `DepartmentID` (PK) |
| `Instructors` | Stores faculty details | `InstructorID` (PK), `DepartmentID` (FK) |
| `Students` | Stores student details | `StudentID` (PK) |
| `Courses` | Stores course offerings | `CourseID` (PK), `DepartmentID` (FK) |
| `Enrollments` | Maps students to courses | `EnrollmentID` (PK), `StudentID` (FK), `CourseID` (FK) |

**Initial seed data:**
- Departments: Computer Science, Mathematics
- Instructors: Alan Turing (CS), Ada Lovelace (CS), Carl Gauss (Math)
- Students: John Doe, Jane Smith
- Courses: Introduction to SQL (CS, 3 credits), Data Structures (Math, 4 credits)
- Enrollments: John → Intro to SQL, Jane → Data Structures

### Query 7 — Popular Courses (More Than 5 Students)

**Objective:** Identify courses with more than 5 enrolled students.

```sql
SELECT CourseID, COUNT(StudentID) AS EnrolledStudents 
FROM Enrollments 
GROUP BY CourseID 
HAVING COUNT(StudentID) > 5;
```

**Explanation:** Groups enrollment records by `CourseID` and counts students per course, then filters groups using `HAVING` (since aggregate results can't be filtered with `WHERE`). With only 2 total enrollments in the sample data, none exceed the threshold of 5.

**Output:**

_(no rows returned)_

### Query 8 — Students Enrolled in Both Specific Courses

**Objective:** Find students enrolled in **both** "Introduction to SQL" **and** "Data Structures".

```sql
SELECT s.* FROM Students s 
JOIN Enrollments e1 ON s.StudentID = e1.StudentID 
JOIN Courses c1 ON e1.CourseID = c1.CourseID 
JOIN Enrollments e2 ON s.StudentID = e2.StudentID 
JOIN Courses c2 ON e2.CourseID = c2.CourseID 
WHERE c1.CourseName = 'Introduction to SQL' AND c2.CourseName = 'Data Structures';
```

**Explanation:** Self-joins `Enrollments`/`Courses` twice (aliased `e1/c1` and `e2/c2`) so each candidate student must have one enrollment row matching "Introduction to SQL" AND another matching "Data Structures" simultaneously. Since John only takes SQL and Jane only takes Data Structures, no single student satisfies both.

**Output:**

_(no rows returned)_

### Query 9 — Students Enrolled in Either Course

**Objective:** Find students enrolled in **either** "Introduction to SQL" **or** "Data Structures" (no duplicates).

```sql
SELECT DISTINCT s.* FROM Students s 
JOIN Enrollments e ON s.StudentID = e.StudentID 
JOIN Courses c ON e.CourseID = c.CourseID 
WHERE c.CourseName IN ('Introduction to SQL', 'Data Structures');
```

**Explanation:** A single join with an `IN` filter (logical OR) instead of the double self-join in Query 8. `DISTINCT` prevents duplicate rows if a student were enrolled in a course more than once.

### Query 12 — Student Count Per Department

**Objective:** Count how many distinct students are enrolled in courses belonging to each department.

```sql
SELECT d.DepartmentName, COUNT(DISTINCT e.StudentID) AS StudentCount 
FROM Departments d 
JOIN Courses c ON d.DepartmentID = c.DepartmentID 
JOIN Enrollments e ON c.CourseID = e.CourseID 
GROUP BY d.DepartmentID, d.DepartmentName;
```

**Explanation:** Chains three tables (`Departments` → `Courses` → `Enrollments`) and groups by department, using `COUNT(DISTINCT ...)` so a student enrolled in multiple courses of the same department is only counted once.

**Output:**

| DepartmentName | StudentCount |
| --- | --- |
| Computer Science | 1 |
| Mathematics | 1 |

### Query 13 — Inner Join: Students and Their Courses

**Objective:** List every student alongside the course(s) they are enrolled in (students with no enrollment are excluded).

```sql
SELECT s.StudentID, s.FirstName, s.LastName, c.CourseName 
FROM Students s 
INNER JOIN Enrollments e ON s.StudentID = e.StudentID 
INNER JOIN Courses c ON e.CourseID = c.CourseID;
```

**Explanation:** An `INNER JOIN` only returns rows where a match exists in all joined tables — students without any enrollment row would be dropped entirely.

**Output:**

| StudentID | FirstName | LastName | CourseName |
| --- | --- | --- | --- |
| 1 | John | Doe | Introduction to SQL |
| 2 | Jane | Smith | Data Structures |

### Query 14 — Left Join: All Students, With or Without Courses

**Objective:** List every student, including those **not** enrolled in any course.

```sql
SELECT s.StudentID, s.FirstName, s.LastName, c.CourseName 
FROM Students s 
LEFT JOIN Enrollments e ON s.StudentID = e.StudentID 
LEFT JOIN Courses c ON e.CourseID = c.CourseID;
```

**Explanation:** A `LEFT JOIN` keeps every row from `Students` regardless of a match; unmatched course columns would show as `NULL`. In this dataset both students happen to have enrollments, so the result looks identical to Query 13 — the difference only shows up if an unenrolled student exists.

**Output:**

| StudentID | FirstName | LastName | CourseName |
| --- | --- | --- | --- |
| 1 | John | Doe | Introduction to SQL |
| 2 | Jane | Smith | Data Structures |

### Query 15 — Students in High-Demand Courses (Nested Subquery)

**Objective:** Find students enrolled in any course that has more than 10 total enrollments.

```sql
SELECT * FROM Students 
WHERE StudentID IN (
    SELECT StudentID FROM Enrollments 
    WHERE CourseID IN (
        SELECT CourseID FROM Enrollments 
        GROUP BY CourseID 
        HAVING COUNT(StudentID) > 10
    )
);
```

**Explanation:** A two-level nested subquery: the innermost query finds `CourseID`s with more than 10 enrollments; the middle query finds `StudentID`s enrolled in those courses; the outer query fetches full student records for those IDs. Since no course in the sample data has more than 10 enrollments, the inner query returns nothing and the whole statement returns no rows.

**Output:**

_(no rows returned)_
